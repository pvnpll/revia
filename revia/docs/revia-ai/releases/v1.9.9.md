## Summary

This release completes **Phase 4** of the AI architecture: Persistent Server-Side Learner Context.
The AI now permanently remembers the user's progress (known concepts, struggled concepts, and recently seen concepts) across sessions. To prevent progress from fragmenting when a user types slightly different goals (e.g. "Kannada" vs "Learn Kannada"), a hidden AI normalization step extracts a universal `subjectKey` before querying the database.

---

## What changed

### Topic Normalization (`topic-normalizer.ts`)
- Added a lightning-fast API call to OpenRouter (`gemma-2-9b-it`) that intercepts the user's raw `goal` and `topic` strings and extracts the core subject field (e.g. `kannada`). 
- This acts as the universal key for the `AiLearnerContext` table, preventing memory fragmentation.

### Context Initialization API (`api/v1/generate/context/route.ts`)
- Added a `POST` route to `/api/v1/generate/context` that runs the normalizer and fetches the context from the Prisma database in a single roundtrip.

### UI Integration (`ai-generator-form.tsx` & `ai-session-viewer.tsx`)
- The Generator Form now hits the initialization endpoint before streaming cards. It passes the normalized `subjectKey` and `context` directly to the active session.
- The Session Viewer's Hybrid Loop now mutates the context using the `subjectKey` rather than the raw topic string, securely persisting the ratings (`1-5`) back to the database.

### Documentation
- Updated `prd.md` to formally document Option A (Hidden AI Normalizer) as the active implementation, while preserving Option B (Subject Taxonomy Dropdowns) for future exploration if API latency becomes a concern.
