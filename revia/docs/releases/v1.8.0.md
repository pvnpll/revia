## Summary

This release unifies the study experience: signed-in practice and Daily Review now use the same Bumble-style swipe cards as guest practice. Same drag physics, card chrome, peek, and edge-tap gestures everywhere — the only difference is the footer: guests get the swipe hint, signed-in users get the 1–5 rating buttons after reveal. Scheduling behavior is unchanged.

## Changed

- **Signed-in practice** — Now renders the full swipe deck (`navigationMode="swipe"`) instead of the flat tap-to-reveal view. Drag, peek, and edge-tap behave identically to guest mode. Ratings still drive `PracticeScheduler`; swiping moves within the queue without rating.
- **Daily Review** — Now uses swipe cards with `noLoop` clamping to the finite due queue (no endless loop; snaps back at the ends). Swipe moves without submitting; only the 1–5 footer submits to the SRS scheduler.
- **Study viewer** — New `noLoop` + `hideSwipeHint` props; ratings footer renders in swipe mode for signed-in users; footer hint adapts per mode (practice loop hint vs. review "reveal, then rate" hint); boundary peek hidden when clamped.

## Migration notes

None. Presentation-only change; `PracticeScheduler` (client) and Daily Review SRS (server) receive ratings exactly as before. No API or schema changes.
