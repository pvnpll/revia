# Revia AI Release: v1.9.2

**Date:** 2026-09-24
**Type:** Patch (Bug Fixes + UX)

## Overview

Fixed consecutive double API calls during background prefetch and removed the AI provider selector from the UI. Ollama Cloud is now the permanent default with OpenRouter (Gemma 4) as the only silent fallback.

## Changes

### Fix: Prefetch Fires Only Once Per Batch (`ai-mode-content.tsx`)
A `prefetchQueuedRef` boolean ref was added to gate the background-prefetch `useEffect`. Previously, every time the session object changed (e.g. when new cards were synced into `session.cards` from the stream), the effect re-evaluated the `cardsRemaining` check and triggered another `handleNextBatch()` call, causing two consecutive API requests. The ref is set to `true` the moment a prefetch is queued and only resets to `false` once `ai.isStreaming` goes back to `false` (stream complete). The trigger threshold was also tightened from ≤4 to ≤3 remaining cards to give slightly more buffer before prefetching.

### UX: Remove AI Provider Selector (`ai-generator-form.tsx`)
The "AI Provider" segmented control (OpenRouter / Gemini / Ollama Cloud) has been removed from the generation form. The provider is now always `ollama` — no user decision required.

### Config: Simplified Fallback Cascade (`ai-generation-service.ts`)
Both `generate()` and `generateStream()` now use a single-step fallback:
- **Primary**: Ollama Cloud (`gemma4:31b` + model cascade)
- **Fallback**: OpenRouter (`google/gemma-4-31b-it:free` as first candidate)
- **Disabled**: Gemini is no longer in any fallback path

### Config: OpenRouter Gemma First (`openrouter-provider.ts`)
Reordered `DEFAULT_FREE_MODELS` so `google/gemma-4-31b-it:free` is tried first, matching the Gemma model used on Ollama Cloud for consistency.

## Breaking Changes
None — the `provider` field in the API still accepts `"gemini" | "openrouter" | "ollama"`, but the UI only ever sends `"ollama"`.
