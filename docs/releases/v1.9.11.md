## Summary

Patched two critical data-sync issues where the Phase 4 persistent memory would fail to read/write under edge cases.

---

## What changed

### 1. Zod Validation Stripping Fix (`generation-request.ts`)
- The generation API was silently discarding the `subjectKey` sent by the frontend because it was missing from the Zod validation schema. This caused the generator to fetch and update the database using the raw, un-normalized topic string, breaking cross-session memory.
- Added `subjectKey` to `generationRequestSchema` and updated `ai-generation-service.ts` to prioritize it.

### 2. LLM Rate-Limit Fallback Fix (`topic-normalizer.ts`)
- If the free `gemma-2-9b` API failed or rate-limited, the normalizer gracefully caught the error but defaulted to the key `"general"`, which would mix memory across completely unrelated subjects.
- Replaced the `"general"` string with a robust regex fallback (`topic.toLowerCase().replace(/[^a-z0-9_]/g, "_").slice(0, 30)`) to ensure memory stays strictly segregated even if the LLM provider is down.

## Verification
- Both `POST /api/v1/generate/context` and `POST /api/v1/generate/cards` now perfectly sync to the exact same normalized `subjectKey`.
