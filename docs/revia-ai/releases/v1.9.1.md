# Revia AI Release: v1.9.1

**Date:** 2026-09-21
**Type:** Patch (Bug Fixes)

## Overview

This patch fixes a critical bug where the Revia AI study session would rapidly fetch two consecutive background batches of cards and generate a random, small number of cards each time. The root cause was a combination of server-side streaming logic not retrying after duplicate filtering, and frontend React state batching allowing multiple in-flight generation requests.

### Fix: Server-side `generateStream` Batch Size Retry Loop
When card generation uses `filterDuplicateCards`, or an LLM like `gemma4:31b` generates slightly fewer cards than requested, the resulting output might fall short of the requested `batchSize`. The streaming logic was previously modified to skip the `maxRetries` loop that normally tops up the generation. We've added this loop back to `generateStream`. Now, if a generation yields fewer cards (due to duplicate removal or LLM cutoffs), the system loops back up to `maxRetries` times, passing updated context, until the batch is completely fulfilled.

### Fix: Frontend `useAIGenerate` Concurrent Abort Bug
Because the frontend depends on React's `useState` for `isStreaming`, rapid events (like swiping cards quickly, or automatic triggers instantly firing because a batch returned fewer cards) could invoke `generate()` a second time before the `isStreaming` state actually updated in the component tree. The second invocation would cleanly cancel the first API request mid-flight via `AbortController`, but preserve the partially streamed cards, leading to random card counts. We've guarded the `generate()` method with a synchronous `useRef` to instantly block any concurrent duplicate calls.

## Breaking Changes
None.

## Test Instructions
- Open `npm run dev` and navigate to the AI card generation.
- Request a topic with a large batch size.
- Scroll through the cards rapidly to trigger the background prefetch (it triggers when 4 cards are remaining).
- Verify that only exactly **one** network request is initiated.
- Verify that the exact requested number of cards are generated and streamed in (minus any unfillable dupes if max retries are exceeded).
