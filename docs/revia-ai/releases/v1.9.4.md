# Revia AI Release: v1.9.4

**Date:** 2026-09-24
**Type:** Patch (Bug Fixes + Provider Fallback)

## Overview

Fixed duplicate consecutive card generation calls, restored accurate background prefetch threshold at 6 remaining cards without false triggers, made Ollama the default provider with automatic OpenRouter (Gemma 4) fallback on all failure types, and surfaced transparent error messages.

## Changes

### 1. Prefetch Guard & Double Call Resolution (`ai-mode-content.tsx`)
- Auto-prefetch is strictly inhibited when `session.currentIndex === 0` (user just received initial batch and has not yet swiped), preventing small initial batches (e.g. 5 cards) from firing an immediate second batch.
- When `handleNextBatch()` is called (either manually via button or automatically via prefetch), `lastRequestedCardCountRef.current` is immediately stamped with `session.cards.length`.
- The background prefetch only fires when the user is actively studying (`currentIndex > 0`), `cardsRemaining <= 6`, and `session.cards.length > lastRequestedCardCountRef.current`.

### 2. Provider Default & Resilient Fallback (`provider-factory.ts`, `ai-generation-service.ts`)
- `createAIProvider` now defaults to `ollama` whenever unspecified (or `openrouter` if only OpenRouter key is set), keeping Gemini disabled.
- In both `generate()` and `generateStream()`, any non-auth failure from Ollama Cloud (timeouts, rate limits, 500s, 502s, 503s, format errors, empty outputs) automatically falls back to OpenRouter using `google/gemma-4-31b-it:free` first.

### 3. Error Reporting Transparency (`route.ts`)
- In `/api/v1/generate/cards`, non-Zod/non-AIProvider errors now output `error.message` instead of masking errors behind the generic "An unexpected error occurred during card generation" string.

### 4. UI Labeling (`ai-session-viewer.tsx`)
- Updated study session header subtitle to display "Ollama Cloud" when `session.provider === "ollama"`.
